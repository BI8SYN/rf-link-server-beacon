# 按部署方式生成SAS命令

目标：sas-command只显示适用的命令和少量必要步骤，避免一次展示所有部署方式。

宿主机beacon.sh只读识别运行中官方SAS容器的镜像及Compose标签，区分本仓库完整栈、其他Compose、独立Docker容器；本机原生SAS通过已安装二进制或活动fmo-sas服务识别。不能根据Beacon自身是否在容器运行推断SAS。多种部署并存或未识别时，交互终端选择；非交互环境明确失败并提示--deployment。只检查元数据，不读取容器环境变量、凭据，不修改实际SAS。

显式--deployment full-stack|compose|docker|native用于自动脚本与教程；只生成所选内容。Go CLI继续独立验链和CRL；部署参数在联网前验证。保留原身份、凭据、只读状态语义和签名隔离。

先增加输出隔离、无效参数、宿主机识别/歧义/强制选择测试，再实现；运行全量race/vet、脚本及Compose检查，构建实际镜像。更新使用教程以显式选择full-stack，避免重定向输出时触发交互。仅本地实现验证，不更改现有生产服务、不调用生产身份、不发APRS。

用户进一步确认：无需完全自动化，优先简化教程与操作顺序。README和建服教程以四步手工流程为主，setup不广播，应用SAS并验证后才start；一行自动发报入口留作已有身份的部署方式。
