# 0001：Docker 交付与远程用户签名

背景：用户要求简单部署，又不希望管理员提取广播身份私钥。本机软件加密、Docker secrets 不能抵抗宿主机管理员。硬件 HSM 不适合首版面向普通 NAS 的普遍安装。

选择：Go Beacon + Docker；用户侧仅有公开证书与访问凭据；独立远端使用每个节点的用户密钥签署 STATION，禁止在线使用 CA 私钥做公告签名。完整栈和仅 Beacon 两入口，均不要求现有原生 Broker 迁移。暂不 fork SAS/EMQX/FAS，通过配置、公开根挂载和受控镜像组合。

代价：联网依赖、远端可用性、令牌滥用风险、签名基础设施运维。不能承诺宿主机管理员无法复制 token。新增 Root 也不自动获得官方盒子信任。

远端API与审批流程见远程契约，项目许可证为MIT。远端密钥设施、SLA与运营策略由服务方负责。
